# hunter/ - the pursuer seam (AI now, human-driven post-jam)

Router for `hunter/`. ALL methods run on the instance world thread (the state machine hops first). The relentless-chase mechanic is the trickiest verified Hytale seam in this mod - see the kweebec techspec (linked from the mod root).

- **[`HunterController`](HunterController.java) is the seam** so the round engine drives a pursuer without caring AI vs human (the asymmetric "play as the Kweebec" mode is architected-for, deferred): `spawn` / `tick` (corruption-speed ramp + override-only aggro) / `onAlert` (gate hard-lock) / `despawnAll` / **`hunterPositions(store)`** (0.3.0; the live hunter world positions the `ScareDirector` reads for the per-survivor proximity vignette) / `spawnWave` (one wave NEAR the survivors, as the hunter encounter script asks for it; a no-op default). [`AiHunterController`](AiHunterController.java) is the only implementation.
- **0.3.0 - weighted ARCHETYPE ROSTER (no longer one role).** `AiHunterController` reads [`../asset/HunterArchetypeConfig`](../asset/HunterArchetypeConfig.java)`.all()` (generic, no hardcoded ids): `spawn` builds a weighted roster gated by each archetype's `SpawnTier` vs the current corruption tier + partySize, honoring `Count`/`Weight`; `applySpeed` now tracks **per-hunter** band state (was a single shared scalar) so each archetype paces on its OWN `SpeedBands`/`BandEffectIds`. The `AiHunterController(String)` ctor is unchanged (the fallback role) so `RoundService` is untouched. The 3 new archetypes (`KweebecNightmare_Lunger` Charge, `_Spitter` MaintainDistance kite, `_Ambusher` Teleport blink) are Variant roles of NEW sibling templates cloned from the Blight template - each REPLACES the Attack-state `Intelligent_Chase` motion with its special BodyMotion BUT retains the de-leashed Seek chase as the always-on fallback, so a rejected special motion degrades to a fast/tanky stalker rather than a broken role. **In-game gate:** that the de-leashed Attack state actually drives the ranged/teleport motion (not melee fallback); Teleport is Experimental.
- **The relentless chase is the ROLE's OWN Hostile AI, NOT a per-tick re-stamp** (the old `role.setMarkedTarget` re-stamp is GONE). The Blight Variant ([`KweebecNightmare_Blight.json`](../../../../../../resources/Server/NPC/Roles/KweebecNightmare/KweebecNightmare_Blight.json)) sets `ViewRange`/`AlertedRange`/`HearingRange` = 256 + `ViewSector` 360, so the role pursues the nearest survivor across the whole arena natively. The **soft leash was removed from the Template Attack state** ([`Template_KweebecNightmare_Blight.json`](../../../../../../resources/Server/NPC/Roles/KweebecNightmare/Templates/Template_KweebecNightmare_Blight.json)): it caused the Attack -> Idle -> re-Alerted infinite re-aggro loop, so the `Intelligent_Chase` exports were moved off `Idle` to `Search` and the hunter never gives up / returns to its den (the arena is bounded, so unbounded pursuit is safe).
- **Perfect Utils `AggroAPI` is an OVERRIDE-ONLY layer** (a HARD dependency, in the manifest `Dependencies`), used ONLY for criteria-based aggro switching the natural AI would not pick: the gate-alert lock + the loudest shrine channeller. `AiHunterController.tick` `taunt`s ONLY when `chooseTarget` differs from the natural nearest survivor, so a SOLO survivor is never taunted (no `AggroComponent` ever lands on them). `chooseTarget` ranks gate-alert > channeller > nearest; an override fires a ~2.5s `taunt` burst (`redirectAggro` hands the target to the combat AI, then expires), `clearTaunt` releases it guarded by `isTaunting`. **Gotcha:** an `AggroComponent` left on a player who DIES crashed teardown via Perfect Utils `removeComponent` (dying player's changed archetype no longer has it); fixed in the Perfect Utils repo ([`Developer-Utils`](../../../../../../../../../../hytale-clients/Developer-Utils), commit dc9524d) AND avoided here by the override-only design.
- **Spawns the pack hostile Kweebec role** (`KweebecNightmare_Blight`, a `Variant` of the pack template `Template_KweebecNightmare_Blight` - a parameterized clone of vanilla `Template_Kweebec_Razorleaf` that exposes `DefaultPlayerAttitude` as a Parameter so the Variant sets it `Hostile`; the vanilla template hardcodes `Neutral`, so a plain Variant-`Modify` of it failed validation) via `NPCPlugin.spawnEntity` at `ArenaLayout.HUNTER_DEN`; `onAlert` hard-locks every hunter onto the single nearest survivor to the gate (the next `tick` taunts them). **Corruption-scaled speed IS live** (not baked-only - the old "no runtime setter" read was wrong): each tick `applySpeed` snaps `ChaseState.hunterSpeed(ruleSet)` to a pre-authored `KweebecNightmare_HunterPace_*` EntityEffect and swaps it on every hunter via `EffectControllerComponent.addEffect`/`removeEffect` (mirroring `CocoonService`), and the engine folds that effect's `ApplicationEffects.HorizontalSpeedMultiplier` into the per-tick walk speed (`MotionControllerWalk.getMaximumSpeed` = baked `MaxSpeed` * the effect multiplier); the role `MaxSpeed` is the 1.0x baseline, the band assets live in the pack at `Server/Entity/Effects/KweebecNightmare/`. Other escalation: darkness + heartbeat tier + the alert lock-on. Full proof + the band ladder: the `kweebec-hunter-runtime-speed` research note in the parent repo.
- **The hunter WAVES are a NATIVE encounter script, `Server/EncounterManager/KweebecNightmare_Hunters.json`** (`Type: Generic`, one `Hunt` state; the engine's `EncounterManager` runs it). Its escalation is five `Continue: true` sibling leaves, each a `Once` sensor over ONE wave: two `ZigFactor` rungs on `kweebecnightmare:corruption_tier` (`Value [1, 99]`, then `[2, 99]`: a ring of hunters spaced evenly 18 blocks around the party's centre) and three on `kweebecnightmare:shrines_lit` (`[1, 99]`, `[2, 99]`, `[3, 99]`: a scatter between 8.4 and 14 blocks of ONE survivor picked at random, with the `TOAST_HUNTERS_DRAWN` toast). `Once` on a leaf IS the cooldown, the cap and the once-gating: the number of rungs is the cap, there is no fire ledger anywhere, and two shrines cleansed seconds apart draw two waves. Each rung's actions are the `KweebecHunterWave` action plus a `SignalWorldEvent` (`zc:wave:corruption` / `zc:wave:shrine`) so the library counts the wave. The script binds no boss and never sends `zc:engaged`, so it never engages, shows no bar and announces nothing (a silent director); it authors no `CleanupOnRemove` because the hunters it draws are the controller's, taken down by `despawnAll`. A per-preset cadence would be a `Type: Variant` of it named from a preset leaf; nothing ships one. A script id shares the NPC role id namespace (a script named after a role REPLACES the role at load), so the file is `KweebecNightmare_Hunters`, an id no role carries.
- **[`HunterWaveType`](HunterWaveType.java) registers this mod's ONE encounter instruction Type, `KweebecHunterWave`** ([`BuilderKweebecHunterWave`](BuilderKweebecHunterWave.java) on `BuilderActionBase`, [`ActionKweebecHunterWave`](ActionKweebecHunterWave.java) on `ActionBase`), from `KweebecNightmarePlugin.setup()` through `NPCPlugin.registerCoreComponentType` BEFORE any builder file is read (the manifest depends on `Hytale:NPC` so the NPC plugin is up), guarded and once. FLAT builder keys with native ranges, the NPC builder vocabulary (never the asset codecs' nested groups): `Archetype` (String, blank = the round's own pick), `Count [min, max]`, `PerPlayer`, `Radius [min, max]`, `Even`, `AroundOnePlayer`, `Announce`; `requireInstructionType(Encounter)` makes it illegal in a role. The action reads the run off the executing encounter entity (`EncounterRuns.runOn`), finds the chase round by the run's OWNER KEY (`RoundService.registry().byId`), and hands the [`HunterWave`](HunterWave.java) record to `spawnWave` through `world.execute` (between ticks, the round's own task queue, the same hop `BossEncounterListener` makes); `Announce` toasts every present survivor when the count rose. It ALWAYS answers the engine finished (a `false` is "still running" and a blocking list waits on it forever), nothing-to-do and failure included.
- **`AiHunterController.spawnWave` is the old rule fire with its gates cut out**: clamp the request (`HunterWave.requested(partySize, seed)` x the room under `maxLiveHunters`, `HunterWave.room`), resolve the positions through the shared `SpawnPlacement` (`ringAround` at one radius drawn from the band when `Even`, `nearPlayer` through the band otherwise; the anchor one random active survivor or the centroid), spawn each through `spawnArchetypeAtPos` and answer how many went down. The archetype is the rung's `Archetype` when it names a role-bound one (taken whatever the tier says; an unknown id warns and falls back), else a weighted pick over the tier-eligible roster, the same `eligible` + `weightedPick` the den roster's `planRoster` uses (a dozen inline lines, this controller's own; no shared roster primitive is involved).
- **[`HunterFactors`](HunterFactors.java) contributes the two ids the script reads**, `kweebecnightmare:corruption_tier` (`ChaseState.corruptionTier()`, 0 / 1 / 2) and `kweebecnightmare:shrines_lit` (`ChaseState.litShrines()`), through common's process-wide `FactorContributions` at setup, so zc-encounter's own `ZigFactor` sensor answers them with no zc change. Each provider walks run payload -> owner key -> round -> chase state; a null anywhere answers null (the vocabulary's fail-closed rule), so the script is inert on a non-chase round or after teardown with no guard written. `HunterFactorsTest` pins the walk over a test-authored round.
- **[`HunterEncounter`](HunterEncounter.java) is the round's handle on the script** (`RoundInstance.hunterEncounter()`, beside `bossEncounter`; the two have different lifetimes, hunters from RITUAL to teardown, the Warden from ESCAPE to its death): `raise(round, world)` at `ChaseMode.beginRitual` calls `EncounterSpawner.spawnWhenLoaded` at the floor-snapped `ArenaLayout.SPAWN` with `SpawnOptions.forRound(roundId, presetId, 1.0, round.presentPlayerIds())` (the owner key is how the factors and the action find the round), adopts the handle on the world thread, and logs a refusal instead of failing the round (a switched-off binding row leaves the den roster hunting alone); `dismiss(store)` at `ChaseRoundMode.onTeardown`, after `despawnAll`, removes only the encounter entity. The binding row `Server/ZiggfreedCommon/Encounters/KweebecNightmare_Hunters.json` carries `EncounterAsset`, `NameKey` (`encounter.hunters.name`) and `Enabled` alone: the server-wide off switch (`mods/ziggfreedcommon/encounters.json` under `kweebecnightmare_hunters` + `/zigencounter reload`).
