# boss/ - the round's side of the Warden fight

Router for `boss/`. The Warden FIGHT is not here: it is the native encounter script `src/main/resources/Server/EncounterManager/KweebecNightmare_Warden_Encounter.json`, which the engine's `EncounterManager` builtin runs (the phases as in-place `ChangeTargetRole` swaps onto the `_Phase2` / `_Phase3` role Variants, the adds through `TriggerSpawners`, the engine boss bar, the `zc:` beats), and what the server owes for it is `ziggfreed-common`'s encounter framework, bound by `Server/ZiggfreedCommon/Encounters/KweebecNightmare_Warden_Encounter.json` (the party health scale, the timing guards, the Warden's own `FeedbackMoments/KweebecNightmare_Warden_*` notices, `Discovery.MapMarker: false`). The parent design authority is the hyMMO note [[zc-boss-framework-update6]]. This package keeps only what neither the script nor the library can know: how the round stands the fight up, and what the round does when it hears it.

- **[`BossEncounter`](BossEncounter.java) is the round's handle on its fight** (`RoundInstance.bossEncounter()`): the encounter entity plus the run id the framework stamped on it before it was added. `raise(round, world)` builds the round's `SpawnOptions` (`optionsFor`: the round id as the run's owner, `RuleSet.presetId()` as its difficulty label, `RuleSet.bossHealthMultiplier()` as the run multiplier the binding row's `HealthPerMember` scale composes with, every survivor still in the round as a seeded member so the whole party gets the bar and the credit wherever they stand) and calls `EncounterSpawner.spawnWhenLoaded` at the floor-snapped `ArenaLayout.GATE`, because the gate chunk is far from the party at the escape beat and an entity added into a non-ticking chunk is unloaded on the spot; it completes on the world thread and adopts the handle, or takes the encounter straight back down if the round ended meanwhile. The two policies the round keeps: the **world-map marker** under the preset's `bossMarker` knob (placed on the engage at the Warden's position, followed every 3 s from the `ChaseMode` ESCAPE tick through `followMarker`, removed on `onEnded`), and the **Emberbloom supply** (`onEngaged` / `onPhase`: a ring of 8 / 10 / 12 clusters at `EMBERBLOOM_RING_RADIUS` around the Warden via `ArenaBuilder.plantClusterRing`, rotated by the golden angle per wave, plus a half-count grove scatter via `plantClusters`; there is no wall-clock top-up, each phase entry IS the replenish). The Warden's position is re-resolved on every read through common's `EncounterSubjects.resolve` + `EncounterLifecycle.anchorOf`, because an in-place role change reissues the boss's reference. `dismiss` at teardown calls `EncounterSpawner.despawn` (the script's `CleanupOnRemove` cascades to the Warden and its adds; a fight still open is settled as a wipe first).
- **[`BossEncounterListener`](BossEncounterListener.java) is this mod's ONE inbound listener on the engine bus** (installed from `KweebecNightmarePlugin.setup()` through `getEventRegistry().registerGlobal`, the same form `ziggfreed-common`'s leaderboard listener uses). It subscribes to the framework's `EncounterEngagedEvent` / `EncounterPhaseChangedEvent` / `EncounterDefeatedEvent` / `EncounterSignalEvent` / `EncounterResetEvent`, matches each to the live round whose `bossEncounter().runId()` equals the event's run id (`roundFor` over `RoundService.registry().all()`; a resolved round or one without a fight is ignored), and reacts: engage and phase to the handle above; **defeat opens the Heartwood Gate** through the unchanged, idempotent `ChaseMode.openGate`; the script's own no-show beat (`NO_SHOW_SIGNAL` = `zc:kweebec:no_show`, sent after twenty seconds in Intro with no boss bound) and a reset before the gate opened (a timeout, an admin `/zigencounter end`) open it too, so the escape is never soft-locked. A listener runs synchronously on the firing world thread, often from inside the engine system that decided the beat (the defeat lands from the death system's tick), so every reaction hops through `world.execute` and re-takes its match inside the hop: it runs between ticks, the way the round's own 1 Hz loop does, never inside another system's iteration.
- **`ChaseMode.enterEscape` bars the gate on "an encounter was REQUESTED"**, not on a standing boss: `requestBoss` returns true the moment `BossEncounter.raise` is called, and the raise's own failure path (a refused spawn, the round ending first) opens the gate on the world thread. `ChaseMode.tick` no longer polls the fight; its ESCAPE branch only follows the marker and checks the extraction hold once the gate is open.
- **The preset knobs are unchanged in shape and re-read in meaning**: `BossEnabled` / `BossBarsGate` / `BossMarker` / `BossHealthMultiplier` as before; `BossId` is now the ENCOUNTER SCRIPT id (`KweebecNightmare_Warden_Encounter` in Nightmare and Hardcore), case-sensitive and carried verbatim by `RoundPresetAsset.toRuleSet` (`RoundPresetBossIdTest` pins it); a preset that enables a boss but names none opens the gate without one. **An encounter script and an NPC role share ONE id namespace** (the engine registers the `EncounterManager` builder category into the same NPC `BuilderManager`, keyed by file name): a script named after a role REPLACES the role at load (`[NPC|P] Replacing asset '<id>' ... with other file '/Server/EncounterManager/...'`) and every marker roster naming that role then fails with `<id> does not exist as a role!`, which is why the script is `_Encounter` and never plain `KweebecNightmare_Warden`. There is no runtime boss override on `KweebecNightmareAPI`: a different boss is a different script id in a preset.
- **The spawn markers ride the arena as BLOCKS** (see [`../arena/CLAUDE.md`](../arena/CLAUDE.md)): `ArenaBuilder` stamps `KweebecNightmare/Warden_Spawners` at the gate (one `KweebecNightmare_Warden_Spawner`, four `KweebecNightmare_Blight_Spawner` block items under `Server/Item/Items/KweebecNightmare/`, each keeping a live manual-trigger spawn marker standing over it: `Server/NPC/Spawn/Markers/KweebecNightmare/KweebecNightmare_{Warden,Blight}_Marker.json`), all inside the encounter's own chunk. The three chase instance templates carry `IsSpawnMarkersEnabled: true` with `IsSpawningNPC: false` (a manual marker never fires on its own; only the script fires it).
- **The retune behind the three phases.** The engine keeps the Warden's CURRENT health across an in-place role change and re-rolls only its maximum (`BalancingInitialisationSystem` fills to full only on a fresh `SPAWN`; a role change re-adds the same holder with `LOAD`), so the `_Phase2` / `_Phase3` Variants' `MaxHealth` (300 / 150) are authored as the health the Warden carries INTO each phase (the script's transitions fire at half the current pool): the bar reads full at every phase entry and the three phases add up to the first role's 600 whichever way the engine turns out to treat the swap in play. The play session measures the bar at each phase entry; the `$Comment` on each Variant says how to retune it.
- **Tests:** `BossEncounterOptionsTest` (the round-to-`SpawnOptions` mapping, with a test-authored rule set) and `RoundPresetBossIdTest` (the id's case survives the preset reader). Everything ECS-bound (the spawn, the events, the markers) is proven by the dev-server boot and the play session, never a unit JVM.
