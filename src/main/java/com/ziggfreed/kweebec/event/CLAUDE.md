# event/ - outbound native events + the unified damage observer

Router for `event/`. The mod-root `CLAUDE.md` "MMO Skill Tree integration" section is the wider context. This package holds the outbound-event integration seam (zero MMO dependency) AND the one damage-observer system.

- **[`RoundEvents`](RoundEvents.java) fires the `api/` `IEvent<Void>` POJOs** (`RoundStarted`/`RoundCompleted`/`KweebecRoundScored`/`PlayerCocooned`/`PlayerRescued`) on the shared Hytale bus: resolve the dispatcher, guard on `hasListener()` (silent no-op with zero listeners), dispatch synchronously on the calling thread, whole body try-guarded. Fire from a WORLD-thread context so a listener can resolve a player then hop via `world.execute`. `KweebecRoundScoredEvent` (carrying the per-player `PlayerScore` map) fires AFTER `RoundCompletedEvent` from `RoundService.resolve` - the MMO capstone reward hook.
- **`RoundEvents.fireInstanceCompleted`** fires the generic ziggfreed-common `InstanceRoundCompletedEvent` (mod id `"kweebec"`) right after `fireRoundCompleted` at both `RoundService.resolve` call sites, so any mod on the shared progression engine can count a round win by preset without knowing this mod's own `Outcome` vocabulary. `RoundService.resolve` maps `Outcome` -> `ResultKind` (WIN on `mode.isWin`, ABORT on `ABORTED`, LOSS otherwise) and resolves `winners` (participants on a co-op win, the winning team's members via `round.teamOf` on a PvP win, empty on loss/abort) before calling it.
- **[`DifficultyScore`](DifficultyScore.java) is the one number a consumer scales rewards by.** A pure, deterministic weighted sum over the RESOLVED `RuleSet` (hunter count, the speed ceiling, cave shrines, the corruption ramp, the base shrine count), floored at 0, so a mutator or a runtime scale raises it automatically. `RoundMode.difficultyScore` computes it for the chase and `computeClash` for the two PvP modes; the answer rides both `RoundCompletedEvent` and the generic `InstanceRoundCompletedEvent`.
- **A consumer (MMO) subscribes via the reflective `registerGlobal` adapter** - it loads these event classes from THIS mod's classloader so `Class` identity matches across the jar boundary (the `AnglersAlmanacAdapter` pattern). When MMO is absent the mod self-contains its own rewards. The event POJOs live in the separate `api/` Gradle module (bundled into the jar minus its `META-INF/services` so the engine does not double-register); never bundle the MMO api jar back the other way.
- **[`MoonbloomCollectSystem`](MoonbloomCollectSystem.java) is the in-round glow-mushroom PICKUP observer** (an `EntityEventSystem<EntityStore, InteractivelyPickupItemEvent>`, query `PlayerRef`, registered in `KweebecNightmarePlugin.setup`). Gather is asset-only (the `*_Plant` `Gathering.Harvest.DropList` DROPS the charge - no Java seam at gather time), so this observer listens to the pickup the engine fires when a player picks a dropped charge in. A cheap `isGatherShroom` pre-filter (Moonbloom + the [`GlowThrowables`](../moonbloom/GlowThrowables.java) family) keeps it inert before the per-player round lookup. For an in-round picker it does TWO things: (1) **stat credit** - a [`Moonbloom.CHARGE_ITEM`](../moonbloom/Moonbloom.java) pickup adds the stack quantity to their [`PlayerRoundState.moonbloomCollected`](../round/PlayerRoundState.java) (Moonbloom is the only stat-tracked gather; the lifetime-stat input delivered via the common leaderboard's `stats` map - see [`../experience/KweebecExperience`](../experience/KweebecExperience.java)`.recordScores`); (2) **gather heal** - if the active preset authors a [`RuleSet.gatherHealthRestore`](../round/RuleSet.java) for the picked ITEM id, it tops the gatherer off by `perShroom * quantity` HP via ziggfreed-common `HealthUtil.heal` (the per-difficulty "scavenging heals you" dial: Amateur 8/8, Nightmare 5/5, Hardcore 2/3 for Moonbloom/Emberbloom; absent key = no heal). Read-only on the pickup itself (never cancels), inert outside a round.
- **[`KweebecDamageSystem`](KweebecDamageSystem.java) is the ONE damage observer** (a `DamageEventSystem` in `DamageModule.get().getFilterDamageGroup()`, registered in `KweebecNightmarePlugin.setup` like `CocoonOnDeathSystem`; `getQuery()` = `Query.any()`). It never initiates damage. Six jobs: (1) **throw-to-stun** - a Moonbloom-caused hit on a non-player mob ANYWHERE freezes it via Perfect Utils `StunMobAPI` + the vanilla `Stun` visual effect (an `isStunned` guard makes it fire once per window; players in the splash are skipped, so no friendly-stun); (2) **damage-taken scoring** - real damage to an in-round survivor accumulates onto `PlayerRoundState.damageTaken`; (3) **Emberbloom friendly-fire guard** - the boss-phase glow-throwable's burst (`GlowThrowables.EMBER_DAMAGE_CAUSE`, identified the same custom-cause way as Moonbloom) is nulled (`damage.setAmount(0)`) on a survivor victim, since vanilla AoE has no asset attitude filter, so a thrown Emberbloom hurts the boss + mobs but never a teammate; (4) **per-difficulty throwable damage** - on a MOB victim whose thrower is in a round, `applyThrowableDamageOverride` replaces the burst amount with the preset's `ThrowableDamage` entry for that damage-cause id, so ONE table tunes every authored throwable per preset; a cause the table does not name (melee, an untuned throwable) is left untouched; (5) **hunter on-hit punishment** - when the attacker is a live hunter (model-id prefix, resolved through `HunterController.resolveOnHitConfigFor`), `applyOnHitPunishment` scales the outgoing damage, stacks the tiered `KweebecNightmare_HunterSlow_1..4` on the victim while hits keep landing inside the proximity window (capped, gated by a per-victim re-apply cooldown, and cleared party-wide through the static `clearAllProximityStacks` when a shrine lights), and resets that hunter's desperation-enrage idle timer; the knobs are the [`OnHitConfig`](../hunter/OnHitConfig.java) archetype-over-`RuleSet` fold. Separately, every hunter hit rolls a 25% snicker private to the victim (`maybeSnickerOnHit`); (6) **the PvP path** - on a Clash / Domination round `handleClashDamage` takes the whole hit: it nulls a stray Emberbloom, cancels same-team friendly fire when `RuleSet.friendlyFire()` is off (killing the hit AND its asset knockback, e.g. a Gustbloom), records the enemy hit and the last attacker on `ClashState` (the `MOST_HITS_LANDED` tally + kill credit on death), and turns a Moonbloom hit on an enemy player into a pure stun. The Gust/Mire effects are pure-asset (no damage-observer touch beyond the throwable-damage table); only Emberbloom (enabled, damaging) needs the friendly-fire guard.
- **GOTCHA - how to identify a thrown item's hit server-side (a reusable Hytale technique).** A burst/AOE interaction's damage (`DamageEntityInteraction`) is sourced from `context.getOwningEntity()` = the **SHOOTER** (the player), NOT the projectile entity (`DamageEntityInteraction.java:192` `new Damage.EntitySource(ref)`), and it is an `EntitySource`, never a `ProjectileSource`. So you CANNOT read the projectile config off the damage source, and you cannot tell a thrown-item hit from a melee hit by the source alone. The robust identifier is a **custom `DamageCause`**: author `Server/Entity/Damage/<Id>.json` (`{Parent:Physical, Inherits:Physical}`, a pack-authorable asset type), make the burst's `DamageCalculator.BaseDamage` key that cause id, and match `damage.getDamageCauseIndex()` against `DamageCause.getAssetMap().getIndex("<Id>")` (cache only a positive index - it resolves after this class loads). The cause travels with the damage independent of source/world; the thrower for attribution is still `EntitySource.getRef()` (the owning shooter).
