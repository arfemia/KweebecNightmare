Held until the maintainer releases it. Built on 0.6.8 against Ziggfreed Common 2.1.0
(`ziggfreedCommonJar` stays the 2.1.0 jar), with the manifest unchanged: `ServerVersion`
`>=0.6.0-pre.13 <0.7.0`, `Ziggfreed:ZiggfreedCommon` `>=2.1.0`, `narwhals:Perfect Utils`
`>=1.0.2 <2.0.0`. Only `gradle.properties` moves (`version=1.2.1`; `api_version` stays 1.0.0).
Every library call 1.2.1 adds is in the 2.1.0 jar (`BlockOps.blockItemIdAt`,
`BlockOps.setInteractionState`), so it runs on 2.1.0; the force-loads below are what keep it right
on 2.2.0, whose `SurfaceProbe` and `SpawnPlacement` read only chunk sections already in memory
(2.1.0 read through `World.getBlock`, which loaded a chunk on the spot). The shipping jar starts on
0.7.0-pre.5.1, where 1.2.0 ends the boot with exit code 6, and its calls link on both lines.

- **Update 7: the corrupted models wear the mod's own particle system.** Update 7 renames the base
  game's `Spectre_Void_Hands`. A model whose `Particles[].SystemId` names a system the server cannot
  find fails to decode, with every role that wears it, and the engine's asset validation then ends
  the boot. Adds `Server/Particles/KweebecNightmare/KweebecNightmare_Void_Hands.particlesystem`, the
  base game's body unchanged (one spawner, `Void_Hands`, the same on both lines), and points the
  seven references at it: the two eye nodes on `KweebecNightmare_HunterCorrupted`, and the eyes,
  `Chest`, `L-Arm` and `R-Arm` on `KweebecNightmare_Warden`. `.gitattributes` keeps
  `*.particlesystem` LF. Test: `ModelParticleSystemsTest` (every system a model names ships in this
  jar under `Server/Particles/`, matched exactly; each shipped system has at least one spawner with an
  id, under a key in the engine's format).
- **Update 7: the shrine lights through `BlockOps`.** `ChaseMode.renderLit` read the furnace with
  `World.getBlockType` and wrote through `BlockOperations.setBlockInteractionState` over
  `ChunkStore.getChunkSectionReferenceAtBlock`. Update 7 deletes `World`'s block and chunk accessors
  (`IChunkAccessorSync`, `ChunkAccessor`, `IWorldChunks`), so a 0.6.8-built jar threw
  `NoSuchMethodError` into the method's catch there and the lit state never showed. It now reads with
  Ziggfreed Common's `BlockOps.blockItemIdAt`, resolves through `BlockType.getAssetMap().getAsset(id)`
  and writes with `BlockOps.setInteractionState(chunkStore, x, y, z, Shrine.LIT_STATE, false)`. The
  shrine counts as rendered only once that write returns true; a section not in memory (the read
  never loads one) leaves it to the next reconcile tick, as before. Test: `BlockAccessorScanTest`
  fails the build on a `World` block or chunk accessor called by name on any receiver but `BlockOps`
  or `BlockOperations`, or any mention of `WorldChunk` or `BlockChunk`, in the main source; comments,
  strings and text blocks are skipped, and fixture tests pin each rule.
- **Force-loads key their columns on 32-wide chunks: `arena/ChunkColumns`.**
  `ArenaBuilder.forceLoadAround` (the exit) and `ShrinePlacement.forceLoadCore` shifted a block
  coordinate right by 4, as if a chunk were 16 blocks wide; a Hytale chunk is `ChunkUtil.SIZE` (32).
  The exit's span (chunk radius 1 around `ArenaLayout.ESCAPE`, z -56) asked for chunk z -5 to -3 and
  missed its own column, z -2, so on 2.2.0 the exit paste's probe could read cold ground and the
  platform land at its fallback height, or not paste at all (the co-op hold is anchor-only and never
  needed it). The shrine core's span (radius 70 around `SPAWN`) was wider than the core and missed
  nothing; it is now exact. The package-private record `ChunkColumns(minX, maxX, minZ, maxZ)` builds
  a span `around` a point (a chunk radius) or `covering` an area (a block radius), every bound from
  `ChunkUtil.chunkCoordinate`, so a negative coordinate floors; `forceLoad(world)` asks the chunk
  store for each column, `GetChunkFlags.SET_TICKING`, and answers one future per column. Test:
  `ChunkColumnsTest` (the exit's span holds the escape's own column; every expected column comes from
  `Math.floorDiv(block, ChunkUtil.SIZE)`, never from the code under test).
- **Every read of ground no player need be near force-loads first: `arena/ColumnLoads`.**
  `ColumnLoads.settled(world, what, x, z, blockRadius, timeoutSeconds)` (and a package-private
  overload over a `ChunkColumns` span) force-loads every column holding a block within the radius and
  answers a `CompletableFuture<Boolean>` that never fails: `true` once every column came back with a
  chunk, `false` once one came back with none (`allReferenced`: the chunk store completes a column it
  could not bring into memory with a null reference, not a failure), the load failed, it outlasted its
  timeout, or the kickoff threw (logged as a WARN naming `what`). The read chained after it runs
  either way, on the world thread, and answers its own fallback over anything still cold, as before
  the load existed. The sites:
  - the exit paste, `ArenaBuilder.pasteExit` (chunk radius 1 around `ESCAPE`, 8 s);
  - every floor-snapped prefab paste, the private `ArenaBuilder.paste` (the anchor's column, 8 s);
  - the cave shafts, `ArenaBuilder.pasteCaveShaft` (the shaft's column, 15 s).
    `ChaseState.caveCarveY` is stored only from a probe over a loaded column; a pass whose load did
    not complete before any height was stored logs a WARN, carves nothing and leaves the cave to the
    +4 s or +9 s pass. On 2.2.0 a cold column had pinned the carve to the fallback, `FLOOR_Y` 79, and
    could leave a shrine unreachable, so `allShrinesLit()` never fired;
  - the shrine detection, `ShrinePlacement` (`coreColumns()`, 8 s), now chained with
    `thenRunAsync(..., world)`;
  - the den roster, `AiHunterController.spawn` (the columns within `denReach(total)` blocks of
    `HUNTER_DEN`, 8 s), now placed by `spawnDenRoster`; `denOffset` and `denReach` are package-visible
    pure cores (`DEN_SPACING` 2.0);
  - each hunter wave, `AiHunterController.spawnWave` (the columns within `HunterWave.reach()`, which is
    `ceil(radiusMax)`, of the anchor, 5 s). `spawnWave` answers `CompletableFuture<Integer>` (the
    `HunterController` default included), takes a copy of the survivor position as its anchor so the
    wave reads the ground it loaded, and places through `placeWave`; `ActionKweebecHunterWave` toasts
    `TOAST_HUNTERS_DRAWN` once the count lands above zero, and routes a failure through `waveFailed`;
  - the Warden's rise point, `BossEncounter.raise` (`GATE`'s column, 8 s);
  - the hunter encounter centre, `HunterEncounter.raise` (`SPAWN`'s column, 8 s).

  A round that resolved while its ground loaded gets no den roster and no wave. Tests:
  `ColumnLoadsTest` (a load that completes, fails, hangs past its timeout, or brings a column back
  with no chunk; the throw logging below), `AiHunterControllerDenTest`
  (`theDenReachHoldsEveryRosterHunter`), `HunterWaveTest` (`theReachHoldsEveryPointTheBandCanLandOn`).
- **Three background chains log a throw.** A throw inside a chained stage only fails the future that
  stage returns, so a chain nothing observes drops it without a line. `ColumnLoads.logFailure(what)` is
  a `whenComplete` stage that logs the read's own throw (unwrapped from its `CompletionException`) as
  a WARN naming the site and leaves the chain's answer as it was. It ends the den roster's chain
  ("hunter den"), `BossEncounter.raise` ("Warden rise point") and `HunterEncounter.raise` ("hunter
  encounter centre"). Tests: `ColumnLoadsTest` (`aThrowFromTheReadAfterALoadReachesTheLogNamingItsSite`,
  `aReadThatCompletesLogsNothing`).
- **Ziggfreed Common 2.2.0 under this mod, with no Kweebec code.** Besides the never-loading reads
  above: `LeaderboardPage` paints its "your rank" footer on `#YourRank.TextSpans` (a `.Text` sink
  never substituted its parameters), and the chase and Clash boards open that page
  (`KweebecCommand`, `KweebecDestinations`, `KweebecResultsActions`, `KweebecClashResultsActions`). A
  `zc:defeated` beat for a boss that got away (it ran past its `Range`, or left the world without
  dying) now settles the run as a wipe and resets with `ResetReason.LEASHED`, paying and crediting nothing;
  `BossEncounterListener.onReset` opens the gate on any reset before the gate is open, so a leashed
  Warden opens it the way a timed-out fight does.
- **Maintenance.** `CHANGELOG.md` is now the frozen archive `patch-notes/archive/changelog.md` (a pure
  rename) and the README points at `patch-notes/` alone. The build and the `api/` module's run the
  family's deprecation gate (`gradle/deprecation-gate.gradle`, a byte copy kept LF by
  `.gitattributes`); the mod calls no deprecated API, so nothing is kept. `build-fatjar.ps1` is gone:
  the plain `build.ps1` jar has been the release since 1.1.0. The `CLAUDE.md` routers are rewritten.
