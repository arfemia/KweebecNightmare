Built on Update 7 (`0.7.0-pre.5.1`, recompiled on the live 0.7.0 jar on release day) against Ziggfreed Common 2.3.0. The Update 7 range release on top of 1.2.1, whose two fixes (the mod's own void particle system, the shrine relight through `BlockOps`) already hold on both builds. Two main-source changes, below: the hunters' spawn and the PvP team spawns' facing; and two content-only achievements with their titles.

- **Range, floor and pin.** `ServerVersion` reads `>=0.7.0-pre.0 <0.8.0`, so an Update 6 server logs the mod as out of range. The `Ziggfreed:ZiggfreedCommon` dependency reads `>=2.3.0`: an Update 7 server refuses Kweebec by name beside the Update 6 build of zc 2.2.0 (whose Play page refresh, spawn anchors and build permission fail silently on 0.7.0) instead of loading it there. The compile pin `ziggfreedCommonJar` moves to `ZiggfreedCommon-2.3.0.jar` with the floor, since the pin names the floor's version as in every sibling. A `javap` diff of the zc references shows the same source links the same zc members compiled against 2.1.0 or 2.3.0, so 1.2.1 also runs beside zc 2.3.0.
- **The Lunger's charge on 0.7.0's ramp keys.** 0.7.0's `Charge` body motion has no `ChargeAcceleration` (an `Unknown JSON attribute` warning per load); it ramps over `ChargeAccelerationDistance` and `ChargeDecelerationDistance`, in blocks, 3 each when left out. `Template_KweebecNightmare_Lunger.json` sets both to 0, which commands full speed (`ChargeAbsoluteSpeed`) from the first tick to the stop, as 0.6.8's `ChargeAcceleration` of 1000 did. `ChargeMotionKeysTest` holds every `Charge` in the mod's roles to both distances and away from the dropped key.
- **Instance discovery `Style`.** The five `Server/Instances/KweebecNightmare_*/instance.bson` templates write `"Style": "Major"` in place of `"Major": true`, which 0.7.0 still reads but flags as deprecated each time an instance loads (one warning per round start). `InstanceDiscoveryStyleTest` checks that no template carries `Major` and that every `Style` is a name the engine's own codec accepts (`ProtocolCodecs.EVENT_TITLE_STYLE_CODEC`, matched case-sensitively; an unknown name fails the template).
- **`ManifestTargetTest`** (the check RPG Stations 1.1.1 carries) holds `ServerVersion` to the server jar the build compiles against and to that line's release, never the next line, and holds the `Ziggfreed:ZiggfreedCommon` floor to the CommonLib jar the build compiles against.
- **Hunters spawn only into a ticking chunk section.** On Update 7 a hunter added into a chunk section that is not ticking is parked into the section on the spot (`spawnEntity` answers null) and returns untracked once a survivor nears. Whether the den's section is ever asleep when the roster goes down is unconfirmed: the den stands one section from the instance spawn, inside a survivor's hot sphere once it has grown, and a wave hunter at a sphere's edge is the other case. `AiHunterController.spawnArchetypeAtPos` now spawns through `spawnWhenTicking` over Ziggfreed Common 2.3.0's `TickingSections.ensureTicking`, which wakes a section in memory first and costs nothing where the section already ticks; each wake it had to make logs one INFO line (`woke the chunk section under hunter role`), and a hunter whose section does not tick after the wake (not in memory, or not awake yet) is skipped with a WARNING. This links 2.3.0-only members (`TickingSections.ensureTicking`, `stateAt`, `State`), so 1.2.2 needs CommonLib 2.3.0 (its floor already says so). Test: `HunterSpawnSectionTest`.
- **PvP team spawns face their authored yaw.** `RoundModeSupport`'s team-spawn teleport passed Ziggfreed Common's `ArenaDefinitionAsset.Anchor.yaw` (degrees, by its codec and javadoc; the Clash and Domination arenas author 90 and 270) raw into `Transform`, whose rotation is radians, so the two teams faced about 117 and 350 degrees. It now converts with `Math.toRadians`. The boss, hunter-encounter and AI-hunter spawns read Kweebec's own `arena/Anchor`, radians by `ArenaLayout`, and were already right.
- **Two achievements and two titles, content only.** `Server/ZiggfreedCommon/Achievements/KweebecNightmare/` and `Titles/KweebecNightmare/` ride the mod's asset pack on Ziggfreed Common's achievement and title engines, with no code. `Kweebec_Hardcore_Escape` counts `INSTANCE_ROUND_WON` with Target `kweebec:chase` (`RoundEvents.MOD_ID` and the chase mode's id) and Qualifier `hardcore` (the preset id the round reports, lower-cased); `Kweebec_Warden_Falls` counts `ENCOUNTER_DEFEATED` on the `KweebecNightmare_Warden_Encounter` script, so it credits only the participants the fight's ledger credits (at least the fight's `MinShare` of its damage; the binding authors none, so the library default holds) and leaves the rest to `ENCOUNTER_ATTEMPT`. Each pays its title through the `Title` reward kind under `Rewards.Auto`, the one reward an achievement pays on unlock, and nothing else. They file under the category `Kweebec_Nightmare`, named by `achievement.category.kweebec_nightmare`; every key is bare in `kweebecnightmare.lang`, en-US only as the mod ships. The `Title` reward and the title engine are 2.3.0's, inside the existing floor. No test (R23): the boot's achievement and title audits check the files.
- **Three unread keys are gone.** `cmd.lb_header`, `cmd.lb_empty` and `cmd.not_in_round` (and their `Lang` constants) left en-US: no code, `.ui` page or asset read them.
