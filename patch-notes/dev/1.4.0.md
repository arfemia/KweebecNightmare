Built on Update 7 against Ziggfreed Common 2.5.0 (the compile pin). The manifest drops `narwhals:Perfect Utils` and moves the `Ziggfreed:ZiggfreedCommon` floor from `>=2.3.0` to `>=2.5.0`, the library that ships `StunControl` and `AggroControl` (R364: the floor moves for newer library API). The Moonbloom stun's `ControlLanding` (CommonLib 3.0.0) is newer than 2.5.0, so the floor and the pin move to 3.0.0 at the 2.0.0 seam, with every repo that needs the new CommonLib. Perfect Utils is no longer a dependency of any kind (R740).

- **The Moonbloom stun lands through CommonLib's one control landing, on the mod's own effect, as a fixed control.** `KweebecDamageSystem.stunMob` and `stunPlayer` share `landMoonbloomStun`, which skips a target already stunned (`StunControl.isStunned`, any effect of the Stunned family, the Moonbloom's own included), so a longer stun is never cut short, and calls `ControlLanding.land(accessor, target, Landing.stun(Amount.of(seconds)).under(MOONBLOOM_STUN_EFFECT).by(source))` through the damage system's command buffer, in seconds (`RuleSet.stunDurationMs() / 1000`), attributed to the thrower. `KweebecNightmare_Moonbloom_Stun` has the vanilla `Stun` as its `Parent` and is tagged `"ZigEffectFamily": ["Stunned"]` and `"ZigControl": ["Fixed"]`: every reader of a stun sees it (CommonLib's `isStunned` and `wake`, a stat or proc that reads the Stunned family, so a stun-cleansing effect ends it early), and as a fixed control it skips what CommonLib's Crowd Control settings say a fixed control skips (as shipped: the target's immunity, the shrink and the Immunity ramp, the carrier's control resistance, the thrower's added seconds), so every throw stuns for the round's full length on every server; only a longest stun a server owner sets for the Stun kind on CommonLib's Control Kinds screen (none as shipped) still caps it. The private `alreadyStunned` guard is gone. The separate vanilla `Stun` visual (`applyStunVisual`, `STUN_VISUAL_EFFECT`) is gone: one effect carries the look, the movement hold and the player input lock, and the landing also cancels the target's running chains and holds a creature's attacks. A thrower is credited `mobsStunned` only when the stun landed.
- **The hunters' taunt is CommonLib's `AggroControl`.** `AiHunterController.tick` opens `AggroControl.taunt(store, survivor, 2.5 s, 256)` where it called `AggroAPI.taunt`, and `clearTaunt` ends it with `isTaunting` and `clear`. The window lives in the world's store, never on the survivor, so the old guard against removing a component from a dead survivor's archetype is no longer needed; the "AggroAPI unavailable" warning is gone with the API.
- **The bloom bombs' Artillery XP ships with this mod.** `Server/ZiggfreedCommon/TrackSources/KweebecNightmare/Mmo_KweebecNightmare_Artillery_Xp.json` pays MMO Skill Tree's Artillery 12 XP a hit for each burst whose Hit tag names the Emberbloom, Gustbloom or Moonbloom, the rows MMO Skill Tree's own Artillery table carried until its 2.0.0. Its top-level `Requires` (`hytale:mod_installed` `Ziggfreed:MMOSkillTree`, `Min 1`) drops the file on a server without MMO Skill Tree. It needs MMO Skill Tree 2.0.0: an older copy of this mod beside MMO Skill Tree 2.0.0 pays no Artillery XP for a burst. With MMO Skill Tree 2.0.0 a bloom held in hand trains Artillery through the game's own `Family` `Bomb` its items inherit, the Mirebloom included.
- **Build and setup.** `build.gradle` loses `perfectUtilsJar` and its `compileOnly`, `gradle.properties` loses `perfectUtilsVersion`, and `KweebecNightmarePlugin.setup` loses the `AggroAPI` and `StunMobAPI` probe. The workspace's `family.properties` drops `Developer-Utils` from `dep.kweebec-nightmare`, so a dev boot stages and loads this mod with no companion.
