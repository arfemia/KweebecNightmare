Built on Update 7 against Ziggfreed Common 2.4.0 (the compile pin) and Perfect Utils 1.3.1. The manifest floors stay `Ziggfreed:ZiggfreedCommon >=2.3.0` and `narwhals:Perfect Utils >=1.0.2 <2.0.0`: the one newly linked library member, `PlayerDisplayNames.plainName`, ships in 2.3.0. Eight new locales, and the rest a debt release: real `/kweebec` subcommands, a content fix for a false MMO boot finding, one display-name fix, and dead code and keys out.

- **Eight new locales.** `kweebecnightmare.lang` ships for de-DE, es-ES, fr-FR, hu-HU, it-IT, pt-BR, ru-RU and tr-TR, each with all 321 keys en-US carries (the new subcommand descriptions included), the Blight Warden, the blooms and the modes named as the family's own files already name them.
- **`/kweebec` registers real subcommands.** `KweebecCommand` took `sub` and `preset` as named optional args, so the engine read `/kweebec leaderboard` as one surplus positional token and refused it; only `--sub=leaderboard` ran. The named `sub` and `preset` args are gone, so a `--sub=` or `--preset=` form no longer parses. Now each `KweebecSubcommand` value is an engine subcommand (`addSubCommand`): its first name, the rest as aliases (`dom`, `leave`, `end`, `lb`, `host`), described by a new `cmd.kweebec.<name>.desc` key. A subcommand that reads an argument (`start` and `clash`/`domination` a preset, `give` a count) carries a usage variant (`addUsageVariant`) with one required `STRING` arg, so `/kweebec start hardcore` and `/kweebec give 10` parse positionally and the bare subcommand keeps its default (`nightmare`, `clash_1v1`, `domination_koth`, 5). A bare `/kweebec` still starts on the default preset; a word that names no subcommand reaches the root's own one-argument variant, which answers `cmd.usage`. The player subcommands declare no permission group, so they inherit the root's `hytale:Adventurer` (`putRecursivePermissionGroups`) and stay open to every player, each on its own generated node (`ziggfreed.kweebecnightmare.command.kweebec.<name>`). The admin ones (`clash`, `domination`, `endall`, `give`, `clashhost`) declare `hytale:Admin` (`setPermissionGroups`) and `requirePermission("kweebecnightmare.admin")`, so the Adventurer group never grants them: `AbstractCommand.hasPermission` refuses a sender without the node (an operator holds `*`) before running one, and `getUsageString` leaves it out of a player's usage listing. Their variants inherit the node. `KweebecSubcommand.mayRun` stays as the second guard; `byName` is gone (the engine resolves names and aliases). Every reply key is unchanged. New keys: the ten descriptions plus `cmd.arg.clash_preset`, `cmd.arg.domination_preset` and `cmd.arg.count`. `KweebecSubcommandTest` gains a check that every subcommand's description and argument description has an en-US line, and loses `anAliasRunsAsItsSubcommand`, which pinned `byName`.
- **The Grove Warden placement names its dialogue.** `NpcPlacements/Kweebec_Grove_Warden.json` gains `"Interact": { "Dialogue": "Nightmares_Intro" }`. With no `Interact`, the MMO's `MmoPlacementValidator.checkQuestList` read the placement as opening the quest list for `KweebecNightmare_Guide` and reported `GIVER_WITHOUT_CONTENT`, and `nightmares_intro` drew `DIALOGUE_WITHOUT_PLACEMENT`, on every boot of the MMO beside Kweebec. Runtime is unchanged: the role opens the dialogue itself through `ZigOpenDialogue`, and the placement still stands aside on an MMO server (`Requires`).
- **The Clash knockout toast names the victim through `PlayerDisplayNames.plainName(uuid, null)`** (Ziggfreed Common's display-name seam), not `PlayerRef.getUsername()` with a `"?"` fallback: an offline victim reads as the start of their id rather than `?`. Same key and param. Clash stays unadvertised, so the player note leaves it out.
- **Dead code out.** The pre-0.4.0 channel-relight state (`ShrineState`'s `progress`, `channeller`, `feedbackStage`, `caveSurfaceTopY`, `setAnchor`, `matchesBlock`; `ChaseState.loudestChanneller`, which always answered null, and the `AiHunterController.chooseTarget` branch it fed), `ChaseState.alertFired` (set, never read) and `shrineAt`; `RoundEvents.fireRoundCompleted`'s 6- and 7-argument overloads, `RoundService.startChase`, `KweebecMode.fromId`, `RoundRegistry.activeRoundCount`, `RespawnPolicy.respawns`, `ExclusionMask.firstClear`, `MutatorConfig.getMutators`, `PresetConfig.getPresets`, `KweebecDamageSystem.clearProximityStack`, `ShrineSubmitInteraction.getCODEC` (registration reads the `CODEC` field); and the `round/RoundPreset` shim enum, with the javadoc and three `Instances/*.json` `$Comment`s that named it. None had a caller in Kweebec, MMO Skill Tree, Mob Scaling or Seasons of Orbis.
- **Eight unread keys are gone.** `lobby.name`, `toast.shrine_lit`, `toast.shrine_progress`, `toast.shrine_channel`, `toast.shrine_flare`, `toast.time_low`, `dialogue.nightmares_intro.npc` and `dialogue.clash_intro.npc`, with their `Lang` constants: no code, asset, `.ui` or `.bson` read them, and the dialogue header name comes from the role's `NameTranslationKey`, never a `.npc` key.
- **`__pycache__/` is ignored**, so the `tools/` scripts' bytecode stays out of the repo.
- **Both encounter binding rows switch off Ziggfreed Common 2.4.0's spoils chest.** `KweebecNightmare_Hunters.json` and `KweebecNightmare_Warden_Encounter.json` write `"Spoils": { "Enabled": false }`, so a won fight never stands the library's chest where its boss fell: a chase round hands out its own rewards on its own screen, and neither row pays loot of its own. Their `$Comment`s say so. On a server running Ziggfreed Common 2.3.0, which the manifest floor still admits, the group is an unread key (the asset loader's unused-key warning for each row) and changes nothing.
